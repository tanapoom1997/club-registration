# แผนงานฝั่ง Admin (Phase 1)

> **สถานะ:** แผน ยังไม่ได้ implement ทำต่อจาก Auth + role guard (#3), `pnpm dev` (#4) และ CI (#5)
>
> เอกสารนี้ขยายความ README หัวข้อ Roadmap Phase 1 ข้อ 2, 3, 7 และเมนู admin ที่ตอนนี้เป็นโครงว่าง ถ้าขัดกับ README ให้ถือ README เป็นหลักจนกว่าจะตัดสินใจและอัปเดต README ในงานเดียวกัน

## เป้าหมาย

admin เตรียมข้อมูลทั้งหมดได้เองผ่านหน้าเว็บ โดยไม่ต้องแตะ DB:

1. สร้างรอบลงทะเบียนต่อชั้น
2. นำเข้านักเรียน ชุมนุม และครูจาก Excel (dry run ก่อน แล้วค่อยยืนยัน)
3. ดูและแก้ชุมนุมรายรอบ (จำนวนรับ / ลงแล้ว)
4. ออกรหัสผ่านเริ่มต้นให้นักเรียน (ดาวน์โหลดได้ครั้งเดียว)
5. ส่งออกรายชื่อรายชุมนุมเป็น CSV/Excel

**ไม่อยู่ในแผนนี้:** admin เพิ่ม/ลบ/ย้ายนักเรียนแทน และรายชื่อรอ (Phase 2), Event log (Phase 4), logic ฝั่งนักเรียนลง/ยกเลิก (Phase 1 ข้อ 4 แยกงาน)

## A1. รอบลงทะเบียน

ตาราง `rounds` มีอยู่แล้ว: `term`, `grade` (1–6), `opens_at`, `closes_at`, `max_active`, `UNIQUE (term, grade)`, `CHECK (closes_at > opens_at)`

**API**

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/admin/rounds` | รายการรอบ (กรองตาม `term` ได้) พร้อมจำนวนชุมนุม/ที่นั่งรวม/ลงแล้ว |
| POST | `/api/admin/rounds` | สร้างรอบ ชน `UNIQUE (term, grade)` → `409 round_exists` |
| PATCH | `/api/admin/rounds/:id` | แก้ `opens_at`, `closes_at`, `max_active` |
| POST | `/api/admin/rounds/batch` | สร้างครบ ม.1–ม.6 ของเทอมในครั้งเดียว (เวลาเหลื่อมกันตามที่กรอก) |

**กติกา**

- แก้ `term`/`grade` ไม่ได้หลังสร้าง (ชุมนุมและการลงทะเบียนผูกกับรอบ) ถ้าผิดให้สร้างใหม่
- ลบรอบได้เฉพาะเมื่อยังไม่มีชุมนุม (FK บังคับอยู่แล้ว)
- แก้เวลาได้ตลอด แต่ถ้ารอบเปิดอยู่แล้วให้ UI เตือนก่อนยืนยัน
- เวลาเก็บเป็น UTC (`timestamptz`) UI รับและแสดงเป็นเวลาไทย
- สถานะ (ยังไม่เปิด / เปิดอยู่ / ปิดแล้ว) คำนวณจากเวลา server ไม่เก็บเป็นคอลัมน์

**หน้าเว็บ** ตารางรอบตามเทอม + ฟอร์มสร้าง/แก้ + ปุ่ม "สร้างครบทุกชั้น"

## A2. อ่านและตรวจ Excel + dry run

**Template** (คอลัมน์เดาไว้ตาม README ปรับเมื่อได้ไฟล์จริงของโรงเรียน) ไฟล์เดียว 3 sheet ชื่อ `students`, `clubs`, `advisors` ส่ง sheet ไหนมาก็ได้ ไม่ต้องครบ เก็บไฟล์เปล่าไว้ที่ `templates/club-registration-template.xlsx` และให้ดาวน์โหลดจากหน้าเว็บ

| Sheet | คอลัมน์ | key สำหรับ upsert |
|---|---|---|
| students | รหัสนักเรียน, ชื่อ-สกุล, ชั้น, ห้อง, เลขที่ | รหัสนักเรียน (`users.login_id`) |
| clubs | รหัสชุมนุม, ชื่อชุมนุม, ชั้นที่เปิดรับ, จำนวนรับ, รายละเอียด | (รอบ, รหัสชุมนุม) |
| advisors | รหัสชุมนุม, ชื่อครู, เบอร์โทร, อีเมล, LINE ID | replace ทั้งชุดต่อชุมนุม |

**ชุมนุมผูกกับรอบ:** admin เลือก `term` ตอนอัปโหลด แล้ว "ชั้นที่เปิดรับ" ของแต่ละแถวชี้ไปที่รอบ (term, ชั้น) รอบนั้นต้องมีอยู่ก่อน ไม่งั้นเป็น error ของแถว

**API**

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/admin/import/template` | ดาวน์โหลด template เปล่า |
| POST | `/api/admin/import/preview` | อัปโหลด (multipart) → ตรวจ + เทียบกับ DB → คืนสรุป **ไม่เขียน DB** |

**ผล dry run**

```json
{
  "fileSha256": "…",
  "students": { "create": 412, "update": 3, "unchanged": 30 },
  "clubs": { "create": 18, "update": 0, "unchanged": 0 },
  "advisors": { "clubsReplaced": 18, "rows": 31 },
  "errors": [{ "sheet": "students", "row": 17, "column": "ชั้น", "message": "ต้องเป็น 1–6" }]
}
```

**ตรวจอะไรบ้าง** (ทุกข้อเป็น error ของแถว ไม่หยุดที่แถวแรก)

- ทุก cell ผ่าน Zod schema ใน `packages/shared` (trim, ความยาวสูงสุด, ชั้น 1–6, จำนวนรับ ≥ 0 เป็นจำนวนเต็ม, เบอร์/อีเมลรูปแบบถูก)
- รหัสซ้ำกันในไฟล์เดียวกัน
- รหัสนักเรียนชนกับบัญชีที่ไม่ใช่นักเรียน (เช่น admin)
- ลดจำนวนรับต่ำกว่าคนที่ลงแล้ว (`capacity < registered`) DB บังคับด้วย CHECK อยู่แล้ว แต่ dry run ต้องบอกก่อน
- advisors ชี้รหัสชุมนุมที่ไม่มีทั้งในไฟล์และใน DB
- นักเรียนเปลี่ยนชั้นทั้งที่มีการลงทะเบียนในรอบของชั้นเดิมแล้ว

**ความปลอดภัยของไฟล์**

- ขนาด ≤ 5 MB (ตั้ง limit ที่ route นี้เท่านั้น ที่อื่นยัง 64 KiB) และจำกัดจำนวนแถวต่อ sheet (เช่น 5,000)
- ตรวจทั้ง extension `.xlsx` และ magic bytes (ไฟล์ zip) ไม่เชื่อ MIME จาก browser อย่างเดียว
- ประมวลผลใน memory ไม่เขียนลง disk อ่านเฉพาะค่า cell ไม่ประเมินสูตร (formula อ่านเป็นค่าที่ cache ไว้หรือ error)
- ไม่ log ค่า cell (เป็น PII) log แค่จำนวนแถวและ sha256

## A3. ยืนยันนำเข้า

| Method | Path | ทำอะไร |
|---|---|---|
| POST | `/api/admin/import/commit` | อัปโหลดไฟล์เดิมซ้ำพร้อม `fileSha256` จาก dry run และ `idempotencyKey` |

**ทำไมส่งไฟล์ซ้ำแทนเก็บผล dry run ไว้ที่ server:** README กำหนดว่า app ไม่เก็บ state บน disk และเป็นเครื่องเดียว การส่งซ้ำ + เทียบ sha256 ทำให้มั่นใจว่ายืนยันไฟล์เดียวกับที่ดูสรุป โดยไม่ต้องมีที่เก็บชั่วคราว

**ขั้นตอน (transaction เดียว)**

1. ตรวจใหม่ทั้งหมดเหมือน dry run ถ้ามี error แม้แถวเดียว → `422 import_invalid` ไม่เขียนอะไรเลย
2. upsert `users` + `student_profiles` (นักเรียนใหม่ได้ `password_hash` ที่ login ไม่ได้ ดู A4 และ `must_change_password = true`) นักเรียนเดิม **ไม่แตะรหัสผ่าน**
3. upsert `clubs` ตาม `(round_id, club_code)` ไม่แตะ `registered`
4. ลบแล้วใส่ `club_advisors` ใหม่เฉพาะชุมนุมที่อยู่ในไฟล์
5. COMMIT แล้วคืนสรุปแบบเดียวกับ dry run

**Idempotency:** ส่ง `idempotencyKey` ซ้ำ หรือส่งไฟล์เดิมซ้ำ ได้ผลเหมือนครั้งแรก เพราะทุกขั้นเป็น upsert (ครั้งที่สองจะเป็น `unchanged` ทั้งหมด) ไม่ต้องมีตารางเก็บ key

**ไม่ลบนักเรียน/ชุมนุมที่ไม่อยู่ในไฟล์** (กันอัปโหลดไฟล์ไม่ครบแล้วข้อมูลหาย) การลบเป็นงาน Phase 2

## A4. รหัสผ่านเริ่มต้น

**ปัญหา:** README บอก "สุ่มรายคน เก็บเฉพาะ hash, admin ดาวน์โหลดได้ครั้งเดียว" ถ้าสุ่มตอนนำเข้า จะต้องเก็บรหัสจริงไว้ที่ไหนสักที่จนกว่าจะดาวน์โหลด

**ทางที่เลือก: แยก "ออกรหัส" ออกจากการนำเข้า**

- นำเข้า (A3) สร้างนักเรียนด้วย `password_hash` ที่ไม่ใช่ PHC string (เช่น `!unissued`) ซึ่ง `verifyPassword` ปฏิเสธเสมอ จึง login ไม่ได้จนกว่าจะออกรหัส
- admin กด "ออกรหัสผ่าน" เลือกขอบเขต (ทั้งชั้น / ห้อง / เฉพาะคนที่ยังไม่เคยออก) → server สุ่มรหัส 10 ตัว เก็บ hash แล้วตอบเป็นไฟล์ `.xlsx` ทันที **ไม่เก็บรหัสจริงที่ไหนเลย**
- ไฟล์หายหรือนักเรียนลืมรหัสก่อน login ครั้งแรก → ออกใหม่ได้ (รหัสเก่าใช้ไม่ได้ทันที และ bump `session_version`)
- ออกรหัสได้เฉพาะคนที่ `must_change_password = true` คนที่ตั้งรหัสเองแล้วจะไม่ถูกทับ (ถ้าต้องการ reset คนที่ลืมรหัส ทำเป็น action แยกรายคนพร้อมยืนยัน)

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/admin/students/password-status` | นับต่อชั้น/ห้อง: ยังไม่ออก / ออกแล้วยังไม่ login / เปลี่ยนรหัสแล้ว |
| POST | `/api/admin/students/initial-passwords` | ออกรหัสตามขอบเขต คืนไฟล์ `.xlsx` (รหัสนักเรียน, ชื่อ, ชั้น, ห้อง, เลขที่, รหัสผ่าน) |

**Migration ใหม่:** `users.password_issued_at timestamptz NULL` ไว้แยกสถานะ "ยังไม่ออก" กับ "ออกแล้ว" (forward-only ไม่แก้ migration เดิม)

**ข้อควรระวัง**

- response ตั้ง `Cache-Control: no-store` และไม่ log body
- ไฟล์เรียงตามชั้น/ห้อง/เลขที่ เพื่อพิมพ์แจกเป็นห้องได้
- งานหนัก: argon2 ~2,500 ครั้ง (ประเมิน ยังไม่ได้วัด) ต้องจำกัดให้ออกทีละไม่เกินหนึ่งชั้น หรือวัดเวลาจริงก่อนเปิดให้ออกทั้งโรงเรียนในคำขอเดียว และ rate limit endpoint นี้

## A5. หน้าชุมนุม

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/admin/rounds/:roundId/clubs` | ชุมนุมในรอบ: รหัส, ชื่อ, จำนวนรับ, ลงแล้ว, เหลือ, ครู |
| PATCH | `/api/admin/clubs/:id` | แก้ชื่อ, รายละเอียด, จำนวนรับ |

- ลดจำนวนรับต่ำกว่า `registered` → DB ปฏิเสธ (CHECK) แปลงเป็น `409 capacity_below_registered`
- เพิ่มจำนวนรับระหว่างรอบเปิดได้ (Phase 2 จะต่อด้วย promote คนรอ)
- รายละเอียดแสดงเป็น text ธรรมดา ห้าม `dangerouslySetInnerHTML` (กฎข้อ 11)
- หน้าเว็บ poll ทุก 5–10 วินาทีตอนรอบเปิด เพื่อดูยอดลงแบบใกล้เคียง real-time

## A6. ส่งออกรายชื่อ

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/admin/rounds/:roundId/export?format=xlsx\|csv&clubId=` | ทั้งรอบ (1 sheet ต่อชุมนุม) หรือชุมนุมเดียว |

- คอลัมน์: รหัสนักเรียน, ชื่อ-สกุล, ชั้น, ห้อง, เลขที่, เวลาที่ลง (เวลาไทย) และหัวกระดาษมีชื่อชุมนุมและครู
- **escape ทุก cell ที่เป็นข้อความ** ที่ขึ้นต้นด้วย `=`, `+`, `-`, `@` (รวม tab/CR) โดยเติม `'` นำหน้า (กฎข้อ 8) ทำเป็นฟังก์ชันเดียวใช้ทั้ง CSV และ xlsx พร้อม unit test
- CSV ใส่ UTF-8 BOM ให้ Excel อ่านภาษาไทยถูก
- รายการนักเรียนที่ยังไม่ลงชุมนุมในรอบ (ไว้ตามตัว) เป็นอีก sheet หนึ่ง
- ตอนนี้ยังไม่มี logic ลงทะเบียน เทสต์จะสร้าง registration ตรงใน DB เป็นข้อมูลสมมติ

## Error code ใหม่ (เพิ่มใน `ERROR_CODES`)

`round_exists` (409), `round_not_empty` (409), `import_invalid` (422), `import_file_mismatch` (409, sha256 ไม่ตรงกับ dry run), `file_too_large` (413), `unsupported_file` (415), `capacity_below_registered` (409)

## เทสต์ที่ต้องมี

- **A1:** สร้างรอบซ้ำได้ 409, `closes_at <= opens_at` ได้ 400, student เรียก API admin ได้ 403
- **A2:** แต่ละกฎตรวจมี error ตรงแถว/คอลัมน์, ไฟล์ปลอม (เปลี่ยนนามสกุล) ได้ 415, ไฟล์ใหญ่ได้ 413, dry run ไม่เปลี่ยนข้อมูลใน DB
- **A3:** error แถวเดียวไม่เขียนอะไรเลย, ส่งซ้ำได้ผลเดิม, sha256 ไม่ตรงได้ 409, นำเข้าซ้ำไม่แตะรหัสผ่านนักเรียนเดิม, advisors ถูก replace, import พร้อมกัน 2 คำขอไม่ทำให้ข้อมูลซ้ำ
- **A4:** นักเรียนที่ยังไม่ออกรหัส login ไม่ได้, ออกรหัสแล้ว login ได้และถูกบังคับเปลี่ยน, ออกซ้ำแล้วรหัสเก่าใช้ไม่ได้, คนที่เปลี่ยนรหัสแล้วไม่ถูกทับ, response มี `no-store`
- **A5:** ลดจำนวนรับต่ำกว่าลงแล้วได้ 409 และค่าใน DB ไม่เปลี่ยน
- **A6:** ค่าที่ขึ้นต้นด้วย `=`, `+`, `-`, `@` ถูก escape ทั้ง CSV และ xlsx, ภาษาไทยอ่านถูก
